4.1 ~30 min

🎯 Loop simple: Task Runner

Prompt listo, template de plan.md, cómo monitorear el progreso y Prompt Pack para descargar.

Qué es:

El prompt mínimo para activar el sistema de loop en Claude Code, pidiéndole que cargue la capability y procese las tareas del plan.md una por una.

Prompt listo:

Carga la skill del bucle y trabaja en plan.md una tarea a la vez

Qué es:

Plantilla de plan.md con tareas numeradas, criterios de aceptación y casillas para que el agente las marque a medida que las completa.

Por qué aprender:

La calidad del plan.md determina la calidad del resultado. Las tareas vagas generan resultados vagos.

Qué es:

Cómo seguir el loop en ejecución: en cada ciclo, el agente realiza la tarea, la valida y programa automáticamente el siguiente wake-up.

Conceptos clave:

Activación del slash loop. Validación por ciclo. Logs de la terminal. Estado de plan.md.

Qué es:

Criterios explícitos de finalización: todas las tareas marcadas, /goal alcanzado, máximo de iteraciones como red de seguridad.

Qué es:

Variaciones del prompt para distintos escenarios: refactoring, migración, documentación, pruebas.

Qué es:

Recopilación de todos los prompts de este módulo en formato copiable, listos para usar de inmediato en Claude Code.

4.2 ~30 min

🐛 Loop intermedio: bot de issues de GitHub

Sesión del orchestrator + 4 workers paralelos, worktrees para aislamiento, database branches con Neon.

Qué es:

Configuración de la sesión principal de Claude Code como orchestrator que despacha workflows de corrección para cada issue en paralelo.

Qué es:

Cada worker opera en su propio worktree de Git, lo que garantiza el aislamiento total del código entre sesiones paralelas.

Qué es:

Neon permite crear branches de la base de datos por worker, lo que evita que los cambios en paralelo entren en conflicto en el schema o los datos.

Qué es:

El pipeline completo: extraer el issue, buscar contexto, clasificar, implementar el fix, validar las pruebas, crear un PR y hacer code review.

Qué es:

Optimización de costos usando modelos más pequeños cuando el razonamiento es simple y modelos más grandes solo cuando es necesario.

Qué es:

Paquete con los prompts del orchestrator, los workers y la revisión, listos para adaptar a tu repositorio.

4.3 ~30 min

🤖 Loop avanzado: Orchestrator Multi-Agent

Documento de Spec como entrada, el orchestrator planifica rounds y workers, validación entre rounds, human-in-the-loop.

Qué es:

El documento de especificación es el documento completo que el orchestrator usa para planificar todo el trabajo, dividirlo en rounds y asignar workers.

Qué es:

El orchestrator analiza la spec y decide cuántas rondas serán necesarias, cuántos workers por ronda y qué tareas recibe cada worker.

Qué es:

Cada worker ejecuta su tarea y guarda los resultados en la base de datos externa (Postgres/Neon), lo que permite que el orquestador haga seguimiento sin depender de la ventana de contexto.

Qué es:

Después de cada round, el orchestrator valida los resultados de los workers antes de iniciar el siguiente round, evitando que se propaguen errores.

Qué es:

Puntos de pausa en los que una persona debe aprobar el resultado antes de que continúe el loop, para evitar el problema de «ejecutarlo durante un día y volver a un desastre».

Qué es:

Paquete completo con prompts del orchestrator, los workers, la validación y HITL, adaptables a cualquier proyecto.

4.4 ~30 min

⚠ Anti-patterns y resolución de problemas

Los errores más comunes, cómo depurar y un checklist visual de "ready to loop".

Qué es:

Loop sin criterio de parada definido: el agente se ejecuta indefinidamente, consume tokens sin converger en un resultado.

Qué es:

Iterar en la misma sesión hace crecer el contexto y degrada la calidad. La solución es usar un estado externo y sesiones separadas por worker.

Qué es:

Cuando varios workers intentan usar el mismo puerto de red, lo que causa fallas silenciosas. La solución es asignar puertos dinámicamente.

Qué es:

Los workers sin aislamiento adecuado (sin worktrees, sin ramas de base de datos) editan los mismos archivos y generan conflictos de merge.

Qué es:

Cómo usar los logs de Agent Control Plane para identificar malas decisiones del orchestrator, workers lentos y errores de propagación.

Qué es:

Lista de verificación visual con todos los requisitos previos que deben comprobarse antes de iniciar cualquier ciclo: condiciones de salida, almacén de estado, aislamiento, presupuesto, observabilidad.
