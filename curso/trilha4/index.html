4.1 ~30 min

🎯 Loop Simples: Task Runner

Prompt pronto, template de plan.md, como monitorar progresso e prompt pack para download.

O que e:

O prompt minimo para ativar o sistema de loop no Claude Code, pedindo que ele carregue a capability e processe as tarefas do plan.md uma por uma.

Prompt pronto:

Load the loop skill, work through plan.md one task at a time

O que e:

Template de plan.md com tarefas numeradas, criterios de aceitacao e checkboxes para o agente marcar conforme completa.

Por que aprender:

A qualidade do plan.md determina a qualidade do output. Tarefas vagas geram resultados vagos.

O que e:

Como acompanhar o loop em execucao: cada ciclo o agente faz a tarefa, valida e agenda o proximo wake-up automaticamente.

Conceitos-chave:

Slash loop wake up. Validacao por ciclo. Logs do terminal. Status do plan.md.

O que e:

Criterios explicitos de conclusao: todas as tarefas marcadas, /goal atingido, max iterations como safety net.

O que e:

Variacoes do prompt para diferentes cenarios: refactoring, migracao, documentacao, testes.

O que e:

Compilacao de todos os prompts deste modulo em formato copiavel, prontos para uso imediato no Claude Code.

4.2 ~30 min

🐛 Loop Intermediario: GitHub Issue Bot

Orchestrator session + 4 workers paralelos, worktrees para isolamento, database branches com Neon.

O que e:

Configuracao da sessao principal de Claude Code como orchestrator que despacha workflows de fix para cada issue em paralelo.

O que e:

Cada worker opera em sua propria worktree Git, garantindo isolamento total de codigo entre sessoes paralelas.

O que e:

Neon permite criar branches do banco de dados por worker, evitando que mudancas paralelas conflitem no schema ou nos dados.

O que e:

O pipeline completo: extrair issue, buscar contexto, classificar, implementar fix, validar testes, criar PR e fazer code review.

O que e:

Otimizacao de custo usando modelos menores onde reasoning e simples e modelos maiores apenas onde e necessario.

O que e:

Pack com os prompts do orchestrator, workers e review, prontos para adaptar ao seu repositorio.

4.3 ~30 min

🤖 Loop Avancado: Orchestrator Multi-Agent

Spec document como input, orchestrator planeja rounds e workers, validacao entre rounds, human-in-the-loop.

O que e:

O spec document e o documento de especificacao completo que o orchestrator usa para planejar todo o trabalho, dividir em rounds e despachar workers.

O que e:

O orchestrator analisa a spec e decide quantos rounds serao necessarios, quantos workers por round e quais tarefas cada worker recebe.

O que e:

Cada worker executa sua tarefa e grava os resultados no banco externo (Postgres/Neon), permitindo que o orchestrator acompanhe sem depender do context window.

O que e:

Apos cada round, o orchestrator valida os resultados dos workers antes de lancar o proximo round, evitando propagacao de erros.

O que e:

Pontos de pausa onde o humano precisa aprovar o resultado antes do loop continuar, evitando o problema de "rodar um dia e voltar pra lixo".

O que e:

Pack completo com prompts do orchestrator, workers, validacao e HITL, adaptaveis para qualquer projeto.

4.4 ~30 min

⚠ Anti-Patterns e Troubleshooting

Os erros mais comuns, como debugar, e um checklist visual de "ready to loop".

O que e:

Loop sem criterio de parada definido: o agente roda indefinidamente, gastando tokens sem convergir para resultado.

O que e:

Looping na mesma sessao bloat o context, degradando qualidade. A solucao e state externo e sessoes separadas por worker.

O que e:

Quando multiplos workers tentam usar a mesma porta de rede, causando falhas silenciosas. A solucao e alocar portas dinamicamente.

O que e:

Workers sem isolamento adequado (sem worktrees, sem database branches) editam os mesmos arquivos e geram conflitos de merge.

O que e:

Como usar os logs do Agent Control Plane para identificar decisoes ruins do orchestrator, workers lentos e erros de propagacao.

O que e:

Checklist visual com todos os pre-requisitos que devem ser verificados antes de iniciar qualquer loop: exit conditions, state store, isolamento, budget, observabilidade.
