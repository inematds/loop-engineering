♾ Anti-Pattern: Infinite Loop Without an Exit Condition

The costliest mistake in loop engineering: starting a loop without defining when it should stop. The agent keeps running, spending tokens, without converging on any result. It is the equivalent of a while(true) without break.

🚨 Symptoms

  • ✗Token costs spiking with no visible output
  • ✗Agent repeats the same actions in successive cycles
  • ✗plan.md has no tasks marked as complete
  • ✗No /goal or max iterations defined

✅ Fix

# SEMPRE combine /goal + max iterations
/goal All tasks in plan.md are checked off
/loop --max-iterations 15 work through plan.md one task at a time

# Para multi-agent: max rounds no orchestrator
"Maximum 5 rounds. If spec is not satisfied after 5 rounds, stop and report what's missing."
2

💥 Anti-Pattern: Context Window Overflow

Looping in the same agent session accumulates context with each cycle. After several iterations, the LLM becomes overloaded: responses degrade, instructions are ignored, and the agent starts hallucinating.

"If you leave it looping for a while, your LLM’s context gets huge, and it gets overloaded. That’s why we need a system that distributes the work across different coding agent sessions."
-- Cole Medin

🚨 Symptoms

  • ✗Response quality degrades after 5-10 iterations
  • ✗Agent "forgets" instructions from the start of the session
  • ✗Answers become repetitive or contradictory
  • ✗Hallucination errors in file and function names

✅ Fix

  • ✓External state: record progress in a database (Postgres), not in the context window
  • ✓Separate sessions: each worker in its own agent session
  • ✓Context trimming: keep only the current state in the prompt, not the complete history
  • ✓Compact/resume: use resumable sessions with context compaction
3

🚨 Anti-Pattern: Port Conflicts in Parallel Sessions

When multiple workers run dev servers or tests that use network ports, they all try to use port 3000 (or 5173, 8080, etc.). The first one works; the others fail silently.

"A lot of different things, like port conflicts, which we also want to resolve."
-- Cole Medin

✅ Fix

# Alocar porta dinamica por worker
export PORT=$((3000 + WORKER_ID))

# Ou usar porta 0 (sistema aloca automaticamente)
node server.js --port 0

# No prompt do worker: instrua a usar porta unica
"Use port {{3000 + worker_index}} for any dev server. Do NOT use port 3000."
4

👣 Anti-Pattern: Workers Stepping on Each Other’s Toes

Without proper isolation, workers edit the same files, create merge conflicts, and overwrite one another's work. This problem has two dimensions: code and data.

✗ No Isolation

  • ✗All workers in the same checkout
  • ✗Same database for everyone
  • ✗Constant merge conflicts
  • ✗Migrations breaking other workers

✓ With Isolation

  • ✓Git worktree per worker
  • ✓Neon branch per worker
  • ✓Merge only after validation
  • ✓Each worker operates within a defined scope
5

🔍 Debugging with Dashboard Logs

Observability is key to diagnosing problems in loops. Without it, you're in the dark. Cole Medin built an open source dashboard exactly for this: to see orchestrator decisions, worker progress, and accumulated cost in real time.

"I have a lot of observability built into this dashboard. Being able to see exactly what decisions are being made here makes it easy to analyze everything, even ask my coding agent to analyze the runs in the database, and then figure out how to improve the loop."
-- Cole Medin

📊 What to Monitor

1

Orchestrator decisions

Which workers were dispatched, with which prompts, in which round

2

Tokens per round

Accumulated cost to identify inefficient rounds

3

Worker statuses

Which ones completed, which ones failed, execution time

4

Validation results

Did the tests pass? Were the spec criteria met?
